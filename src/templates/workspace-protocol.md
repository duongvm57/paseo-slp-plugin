# Workspace Protocol

Adapt this basis to repository evidence and Human decisions. Keep effective
tactics here, operational facts in Repository references and global rules in
installed role policy. Blank fields are open decisions, never grants; resolve
them before dependent work. Lead passes relevant constraints to Peer.
Frontmatter records owner/version/scope/review, routing and notebook location;
package_version/template_sha256 preserve rendering provenance. agent_mode is
a direct-launch fallback when the chosen bundle supplies none; ask Human if
neither resolves.

## Workflow choice

Lead chooses the smallest useful method from outcome, uncertainty and risk.
Record the choice/reason and what would change it; reassess before affected
work grows. These paths can combine and adapt without widening phase grants:

| Outcome | Method and completion |
|---|---|
| Clear reversible change with clear verification, no authority/delegation/lifecycle/integrity change | Lean: short inline brief/formation → one authorized writer's edit/check loop → paused stable candidate, actual proof and in-session handback → Lead inspection/Gate/verdict. Peer is default; direct Lead writes need the grant below. No mandatory plan/report files. A failed premise/prerequisite goes to its owner. |
| Coherent behavior with open acceptance/contract or coordinated parts | Feature: settle acceptance and the contract needed by each slice → owner/base/dependency/readiness map → build → authorized single-owner integration → Gate on the integrated outcome. Slice approvals do not accept integration. |
| State/data movement, phased rollout or hard-to-reverse recovery | Transition: inventory/invariants and data owner → runbook/preflight/rehearsal/recovery → Gate on preparation → separate execution checkpoint/grant for the accepted candidate/environment/window/backup → receipts and reconciled post-state → outcome verdict/Delivery. Without recovery, decide that limitation before execution; invariant failure stops it. Script exit 0 and pre-execution ACCEPT prove no reconciled outcome. |
| Cause, evidence or a choice among options | Investigation: bounded question/sufficiency/experiment scope → sources, observations, rejected hypotheses and limits → recommendation/counterargument/reversal conditions when asked → Gate/verdict on the conclusion. Experiments need write scope; a cause grants no repair. Insufficient evidence can be a valid bounded conclusion. |

Route undecided premises/contracts to investigation before tests pin them.
For cross-module ownership/lifecycle/migration/security uncertainty, use a
read-only Architect before foundational implementation; independent design or
sealed council addresses costly choices/disagreement under installed rules.
A large disruptive dependency needs its own bounded contract/handback and
integration owner. Lean leaves its tiny procedure when it needs another
implementation owner, a design seat or Transition phase.

## Gate

Independent review triggers across methods:

- Auth/permissions, money, PII, data integrity or lifecycle/ownership risk.
- Hard-to-reverse architecture/contracts or material cross-module behavior.
- Acceptance established checks cannot sufficiently prove, uncertain writer
  proof, or explicit Human/assignment review.

Record the reasoned review selection before the candidate round under installed
references/review-gates.md: minimum sufficient independent mandates for
material questions, or not-required only without a trigger. Required review
and authorized waiver remain distinct; this basis grants no trigger exemption.
Record a task-selected stop condition and authorized effort/resource bound
before correction/review/challenge. Stop at sufficient proof, unresolved
premise/prerequisite or exhaustion; exhaustion is not ACCEPT.

Lead freezes the paused candidate, inspects measured proof or independently
verifies shell-reported checks, and rules
ACCEPT/CHANGES_REQUESTED/BLOCKED. Corrections and re-review follow installed
Session continuity on the new candidate; recurring classes reopen mechanism/
strategy within the bound. Delivery uses the granted actor/destination and
completion point below. Acceptance, Delivery and resource settlement remain
separate under installed monitoring/record rules.

## Repository configuration

Fill applicable settings from evidence/current assignment; add no setup
ceremony for unused paths. Configuration fields can coexist and select no
Lead type. One Lead is default; split only for authority/capacity under a Human
formation mandate. External intake tools/credentials/polling belong to the
harness; existing desk tools keep their own reservations, pins and evidence.
Use installed task-execution.md for operation instead of duplicate ledgers;
ordinary/Lean routes retain their direct-launch verification. Short work with adequate notifications
needs no heartbeat; gaps/long work may call for a bounded fallback under
installed monitoring.md, with task-specific owner/cadence/expiry/stop.

| Field | Decision |
|---|---|
| Domain, dominant risk and expensive-to-reverse decisions | Resolve from evidence before dependent work |
| Additional Human decisions | None recorded; reserved Human decisions pause dependent work and never default to Lead |
| Assignment and execution | Human/Supervisor route; per-task repo/base/remote, write scopes, environments and phase grants |
| Capacity and isolation | Before concurrency: writer/reviewer limits, merge-safe scopes/resources, actual paths/dependencies, integration owner and candidate freeze; then choose shared checkout or isolation |
| Direct Lead write grant | None by default; Human may specify clear reversible scope, proof/review bounds here or in an assignment |
| Shared-state execution | Per Transition: executor/environment/window, rehearsal, backup/recovery and reconciliation evidence |
| Work state | Current desk projection for admitted operations when used; authorized brief/checkpoint for semantic decisions or ordinary work |
| Delivery/completion | Granted actor, artifact/destination, receipt and completion point per assignment |
| Routing | routing_intent: inherit/pinned/empty; Human owns pool maintenance/budget/quota fallback; option IDs stay in catalog |

Use established checks from the repository/assignment, never commands inferred
from this template. Checks requiring a clean environment use a full whitelist
or complete removal of injected variables; partial unsetting can fake failures.

the conditional Jev branch and fresh runtime evidence.
