# Observe, wait and settle

Supervisor/Lead use this before observation/delegated waits and at settlement.
Events/detectors/heartbeats signal attention; judgment remains with the owner.
The package is no background lifecycle runner. If supported, opt-in
`slp.mjs monitor` is an on-demand delta scan producing signal candidates,
not verdicts or live turns.

## Observation route

Record task/project, observer/Lead IDs, scope, baseline resources, evidence
cursor/checkpoint and report route. Discover available tools: finish wakes,
timeline/report access, heartbeat controls and cross-session reports are
separate capabilities. For managed tasks consume their bound attempt/effect receipts; for direct
formation verify actual parent/workspace/report route under delegation-execution.md.
Record unexposed metadata and retain the assigned recipient.

Enumerate seats by parentage, assignment labels and provider prefix, not cwd:
worktrees run different paths and refs/heads/<lane> receives lane commits
before shared-branch integration. Keep IDs/creation
receipts; verify a missing listing by ID before diagnosing absence or
replacement. Empty inventory proves no settlement.
Use notifyOnFinish=true on create/follow-up. Material decisions, new
assumptions, ambiguity, reopen/dependency requests, repeated failures,
stalls and stable candidates/findings warrant bounded reports with evidence
and attention needed. Peer→Lead and assigned Lead→Supervisor use pinned
routes; a parent label resolves a missing recipient only when that relation
matches. Informational reports need no acknowledgment prompt.

Without a semantic event bridge, record the coverage gap: finish callbacks
do not prove mid-task detection. Use explicit material reports and a
justified fallback wake within authority. No authorized path meeting the
observation need makes dependent work BLOCKED.

## Heartbeat safety net

Choose a bounded fallback for gaps in event coverage only when the
protocol/assignment calls for it. Short work with adequate events needs none.
Duration/risk/coverage determine cadence, timezone, expiry/run limits and
owner; no universal interval applies. When periodic coverage is selected,
arm the bounded task-local wake before ending with delegated work outstanding
and delete it when the needed report arrives.

Discover create_heartbeat in the agent-scoped session; rejection is a
capability gap, allowing finish/mailbox wakes within authority or BLOCKED.
Check the existing task receipt to avoid duplicates. Record returned ID,
owner, task, cadence, expiry and stop condition durably. Its prompt names
agents/task and the live checkpoint/state path to read, not embedded stale
state; ask for material delta, evidence and authorized escalation.
It grants no implementation or post-stop revival.
On each wake, inspect once, advance the checkpoint for new evidence and
return to event waiting; no material delta needs no intervention.

Use discovered delete_heartbeat({id}); assume no list/update API. Retain
receipts across recovery. For cadence changes, confirm deletion before a
replacement. Missing receipt/control is a settlement gap. A create_schedule
launches fresh sessions rather than waking this observer: use only for
separately assigned recurring work after verifying role loading, placement,
parentage/settings, and retain IDs/stop conditions. A periodic sweep, when
chosen, is one bounded owner-map/timeline pass outside a status loop; the
heartbeat stays a safety net.

## Signal and intervention

Read indicated status/activity and relevant timeline/Git/workspace delta.
Retrieve actual report/candidate; curated activity is tail-oriented and can
truncate into overflow files. Widen the limit/read the overflow rather than
infer completeness; unavailable report access is an evidence gap.
At every material event scan for repeated scope/file corrections,
out-of-scope writes, status/tests promoted to acceptance, implementation-
mirroring tests and mocks hiding failure paths. A hit uses governance.md
as a hypothesis, not a diagnosis. Distinguish waits, permissions,
prerequisites and lost momentum; use observation/evidence/open question to Lead.

Before correction prompts, compare current activity with the checkpoint.
Prior tool errors do not establish a stall; corrected requests and checks
are progress. Prompt running work only when intervention warrants interrupting
its mutation. Continue an evidenced idle owner only with actionable work and
no pending wait, or explicit recovery authority. Log every prompt's timestamp
and pre-send state; later success proves no necessity. Preserve interrupted
operations/uncertain effects for recovery; ambiguous creates follow
delegation-execution.md. Inspect quota/auth/tool/authority and changed
prerequisites before retrying; identical retries add no evidence. Numerical
retry examples are repository choices.

## Settlement and stop

At completion, cancellation, handoff or expiry, reconcile task owner/resource
receipts: descendants, permissions, terminals, scripts, schedules/heartbeats,
processes and worktrees. Settle each bounded task after Delivery completes
and no correction or re-review remains open. Retain the same write owner and
independent seats for open rework under orchestration.md's Session continuity;
each granted correction freezes and re-enters its gate. Effort exhaustion
leaves obligations open, not accepted. A continuing Lead/lane does not keep
a completed task open. Archive after reconciled settlement only through
authorized host controls; report unavailable control/unknown quiescence.
For desk tasks, use slp_task_reconcile and current workflow resource/delivery
rows under task-execution.md, rather than duplicate receipt bookkeeping.
Account separately for resources outside that ledger and proof gaps it retains.

Apply common policy on Human stop: no new work/follow-up/cleanup agents.
Each heartbeat owner deletes its recorded task heartbeat and records the
receipt. Arrange another owner's cleanup during normal handback; after stop,
missing authorized controls leave unknown settlement without a new work prompt.
Expiry evidence alone proves no expiration. Stop owned schedules/other
resources only through authorized discovered controls, preserving baseline
resources and continuing portfolio monitoring.

Hand back verdict/candidate separately from resource IDs, cleanup receipts,
continuing assignments, unknown settlement and reproduction/downstream inputs.
Idle/deadline proves no cancellation, cleanup or technical acceptance.
The receiving owner writes the settlement record under report-records.md
only after Delivery and closed rework; that reference owns sinks and timeline
handle/export limits. A pointer cannot restore a removed host timeline.
