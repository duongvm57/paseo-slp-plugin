# Select and operate runtimes

Human owns bundles/pool/budget/fallback. Supervisor/Lead use saved profiles;
Peer uses the assignment's pool. Role experiments need separate authority;
dispositions imply no fixed model.

## Saved Supervisor/Lead profile

slp_seat_create resolves slp-lead, refreshes providers, revalidates before
create/delivery and observes the runtime. Supervisor child formation uses
CLI compatibility; Supervisor can still form Lead through the desk.
Saved profiles select neither Peer pools nor Jev.
Use common policy's once-per-session route verification. If PASEO_AGENT_ID is
unavailable, slp_status({}) supplies identity/workspace for one bounded host lookup;
record missing parent/report metadata as a gap.

Compatibility/unbound hosts: prepare role/repository/workspaceId/assignment
and optional taskLabel. prepare --live --emit create --paseo-home <verified-home>
resolves saved profiles against fresh providers and emits arguments only.
Use prepare --schema when unfamiliar. Preserve supplied live arrays verbatim or
use inventoryFile; inline providers win. --emit create validates; --check diagnoses
rejection, not a required second pass. Verify settings/parent/placement.
Profile/option pins precede protocol agent_mode; unresolved mode needs Human.
Missing profiles/unavailable providers block; configured inventory proves no live
availability. Preparation/host create are not atomic.

## Peer pool

Start with runtime/selection omitted for ordinary/Lean slp_seat_create; consume
its result via delegation-execution.md. Runtime discovery and Jev decisions
belong to that server operation. Full runtime pins select compatibility and
must include required receipts. A linked caller without local routing/protocol
inherits its configured same-Git main checkout; no trustworthy source means
gap, not silent user fallback. Repository catalogs win even when empty;
otherwise only Manager's user pool is fallback. Preserve routing_intent;
report poolDrift/warnings for Human reconciliation, never auto-merge.

Armed Jev selects through a retained decision; error blocks the branch.
Shadow requires independent Lead selection even for one option; errors block.
V1 Off/unconfigured selects a sole eligible option; several options return
choices for selection.optionId. V1 settings/token semantics remain until Human
conversion. Read references/jev-routing.md for shadow/armed/error, skipping unconfigured/off.
Old optionId/catalogSha256/decision pins remain supported; armed decline/config/key/network
failure blocks without default substitution. The runtime resolves the complete bundle
against fresh host providers before effects; eligibility proves no suitability/quota.

V2: read every preset's description/hints, including custom entries, against
the outcome, uncertainty, constraints and proof. Names/origin/order/disposition
are not classes. Choose selection.optionId + selection.thinkingOptionId (null
for runtime default); one model with several efforts has several choices.
For cross-provider, name the author/opinion source in routingRequirements.referenceAgentId;
add crossProvider:true when the assignment requires it across the pool. Missing
model-vendor identity is a gap; wrappers prove no different vendor. Keep explicit
rules/effort limits. Preserve selectionSha256/routingContext in compatibility;
Shadow compares independent pairs, Armed pins Jev's pair. No effort overlay,
mid-turn changes, retry ladder or extra budget.

## Explicit dispatch and compatibility

Task dispatch needs pool/Jev pins. CLI compatibility uses slp.mjs routes
<absolute-repository> --paseo-home <home>, live list_providers and Peer pins
in prepare --emit create; prepare never calls Jev. V2 route-choices <request.json|-> discovers pairs offline with fresh model
capability observations. Preserve complete settings/exact IDs including slashes;
never inherit effort/features or bypass routing with bindings.

## Quota and transfer

On actual quota failure record source/operation/provider proof. Missing/disabled
quotaFallback stops. Human-authorized fallback designates one eligible option,
one attempt within budget: refresh routes, prepare/dispatch with quotaFallbackFrom.
Reject known shared exhausted quota; different models prove no spare quota.
Another failure ends the attempt, never a search or new entry.

Provider changes need authorized old-writer settlement, fresh session and handoff;
same-provider context reuse stays within ownership/settings. prepare-handoff
validates claims/measures candidate, not settlement/acknowledgment. Use governance.md
for resources/transfer. Children retain parentage; discover successor control,
preserving unknown wakes/one writer. No-offer desk succession permits no cold
takeover. Quota alone creates no switch/cost authority; Human instructions or
standing fallback do. Only authorized Human configuration changes profiles/pool;
preserve failed sessions/evidence.
